# 基于市场环境的电力系统规划仿真平台 · 系统设计说明 v1.0

依据：已验证的《源网荷储规划算法》v0.4（`algorithm/` 包，Gurobi 13.0.3 实测通过）。
本文定义前后端需求与接口契约，作为开发依据。算法层只封装、不改动。

---

## 1. 使用流程（与用户口径一致）

```
① 设置电力系统 ──► ② 设置运行边界 ──► ③ 设置出清/算法参数 ──► ④ 执行计算 ──► ⑤ 结果与可视化
     system              scenario              params                job              result
   （版本化）          （挂在系统版本上）      （可存为方案）        （异步）        （图表+明细+导出）
```

关键设计决定：

1. **系统模型版本化**。模块1 与模块2 引用同一 `system_id@version`，规划新增资产生成新版本，历史任务结果可复现。
2. **运行边界与系统版本绑定**。负荷/新能源/区外来电的时序数据属于某个系统版本，避免"改了拓扑但边界没同步"。
3. **计算全部异步**。求解以分钟计，前端只提交任务、轮询进度，不阻塞。
4. **校验前置**。数据规范第 8 节的校验（预测值>容量上限、Pmin vs 低谷负荷、投资上限量级）在 ②③ 步实时执行，不要等 ④ 步求解器报 infeasible。

## 3. 算法参数契约（= SolveOptions 的服务化）

```json
POST /api/jobs
{
  "kind": "clearing",
  "systemId": 3,
  "scenarioId": 7,
  "params": {
    "dt": 1.0,
    "budget": 1000000000,          // 投资上限 B（元）
    "curtailPenalty": 500,          // 弃新能源惩罚（元/MWh）
    "annualize": false,             // [修正项] 投资年化 + 运行年化
    "years": 20,
    "discount": 0.08,
    "resMinShare": null,            // [修正项] 新能源电量占比下限，如 0.32
    "essLpRelax": false,            // 默认 false：松弛会产生同时充放虚拟卸荷（已实测）
    "timeLimit": 300,
    "mipGap": 0.0001,
    "tieAdjustable": false          // [预留] 区外来电可调区间
  }
}
```

`params` 即 `SolveOptions` + 规划经济数据（B、c_curt）的并集，前后端共用同一 schema 文件生成表单与校验。

## 4. API 契约

### 4.1 系统建模（步骤①）

```
GET    /api/systems                      系统列表（含版本）
POST   /api/systems                      新建
POST   /api/systems/{id}/versions        派生新版本（复制拓扑）
GET    /api/systems/{id}/nodes|lines|units|ties
POST   /api/systems/{id}/units           单条增改（表格编辑）
DELETE /api/units/{uid}
POST   /api/systems/{id}/import          批量导入（上传 8 个 CSV 的 zip）
       → 200 { "errors": [...], "warnings": [...], "imported": {...} }
GET    /api/systems/{id}/export          导出 CSV zip（与规范文件名一致）
```

导入复用 `algorithm/data_io.load_case()` 的字段映射与校验，错误按行号返回。

### 4.2 运行边界（步骤②）

```
POST   /api/scenarios                    { systemId, name }
PUT    /api/scenarios/{id}/load          批量上传（CSV 或 JSON 数组）
PUT    /api/scenarios/{id}/res
PUT    /api/scenarios/{id}/ties
GET    /api/scenarios/{id}/curves        聚合曲线（前端绘图用）：
       → { "loadTotal": [{t, mw}], "resTotal": [...], "tieTotal": [...],
           "netLoad": [...], "perNode": {...} }
POST   /api/scenarios/{id}/validate      → { "blocking": [...], "warnings": [...] }
```

`validate` 返回三类结果：
- **blocking**：已建机组 Pmin 之和 > 低谷负荷（必然 infeasible，禁止提交）
- **warning**：新能源预测值 > 装机上限（截断或修正）
- **info**：投资上限与待建成本的占比、拓扑连通性

### 4.3 执行计算（步骤③④）

```
POST   /api/jobs                         提交（参数见第 3 节）→ { jobId }
GET    /api/jobs                         任务列表
GET    /api/jobs/{id}                    状态：pending/running/succeeded/failed
GET    /api/jobs/{id}/events             SSE 进度推送（presolve / 求解进度 / 校验）
POST   /api/jobs/{id}/cancel
```

任务状态机与失败语义：

```
pending → running → succeeded
                  → failed(数据错误)     message = DataError 文本（含四类原因排查指引）
                  → failed(不可行)       message + infeasible.ilp 下载链接
```

不可行时**不静默**：返回 IIS 冲突约束清单（解析 ilp 文件提取约束名），前端按 M1~M5 分组展示。

### 4.4 结果与可视化（步骤⑤）

```
GET /api/jobs/{id}/result/summary          指标卡片数据（对应 结果汇总.json）
GET /api/jobs/{id}/result/investments      投建表
GET /api/jobs/{id}/result/dispatch         出力明细（分页 + ?group=kind 聚合）
GET /api/jobs/{id}/result/storage          储能三列（含 t=0 初始 SOC 行）
GET /api/jobs/{id}/result/curtailment
GET /api/jobs/{id}/result/flows            线路潮流（由 PTDF 反算，供热力图）
GET /api/jobs/compare?ids=1,2,3            多方案指标对比（S1/S2/S3 表）
GET /api/jobs/{id}/export                  导出 CSV/ZIP
```

## 5. 前端页面结构（React + TS + AntV/ECharts）

### 步骤① 电力系统建模
- 左侧：拓扑树（节点 → 挂接机组/联络线）；右侧：数据表格（Ant Table 行内编辑）
- 顶部：版本切换 + 新建版本；导入/导出按钮
- 机组类型下拉固定 1~6 编号；储能必填可用小时数与效率

### 步骤② 运行边界
- 三张曲线图：总负荷/分区负荷（堆叠）、新能源出力（分机组）、区外来电
- 曲线支持 CSV 导入覆写；单点拖拽微调（二期）
- 底部常驻校验面板（红=blocking / 黄=warning），未通过不允许进入下一步

### 步骤③ 出清/算法参数
- 分组表单：**经济参数**（B、弃电惩罚）｜**年化**（开关+年限+折现率）｜**政策**（新能源配额）｜**求解器**（时限、MIPGap、z 松弛开关）
- 每项带单位与默认值；修正项开关旁标注对结果的影响（引用实测三方案差异）

### 步骤④ 执行计算
- 任务卡片：状态、进度条、已用时间、Gurobi 日志尾部（可折叠）
- 失败态：错误分类 + 修复建议 + IIS 冲突约束列表

### 步骤⑤ 结果与可视化
| 图表 | 类型 | 数据源 |
|---|---|---|
| 投建结果 | 卡片表 + 堆叠条形（按类型） | investments |
| 24h 出力构成 | 堆叠面积图（燃煤/燃气/核电/光伏/风电/储能净/区外来电）+ 负荷线 | dispatch 聚合 |
| 净负荷与储能 | 双轴折线（净负荷 + SOC） | storage + 聚合 |
| 弃电分布 | 热力图（新能源机组 × 时段） | curtailment |
| 线路利用率 | 热力图（线路 × 时段，利用率 %） | flows |
| 指标卡片 | 供电成本/弃电率/新能源占比/投资额/投资余额 | summary |
| 多方案对比 | 分组柱状 + 雷达（可切换） | compare |

导出：当前方案 CSV zip；对比表 Excel。

## 6. 技术栈与工程结构

```
backend/   FastAPI + SQLAlchemy + Pydantic（schema 与前端共享生成）
           任务执行：ThreadPool/ProcessPool（单机足够；分布式时换 Celery，接口不变）
frontend/  React + TypeScript + Ant Design + ECharts + Zustand
共享/       params.schema.json —— 前端表单与后端校验的唯一事实源
```

算法对接：`services/solver.py` 直接构造 `CaseData`（从 DB 装配，不落 CSV）→ `SGLSModel` → 结果写库与文件。**`algorithm/` 包零改动**。

环境约束（必须写进部署说明）：
- Gurobi 为受限许可证，**变量/约束上限 2000**，适用于演示与小算例；正式算例需购买 license 或切换 HiGHS（`solver.py` 预留适配层）。

## 11. 平台模块架构（2026-11-03 补充）

平台由两个一级功能模块组成，UI 侧边栏以「模块切换组」呈现：

| 模块 | 状态 | 说明 |
|---|---|---|
| ① 电力系统规划 | 本期建设 | 含五步流程：建模 → 运行边界 → 算法参数 → 执行计算 → 结果分析 + 规划前后对比 |
| ② 电力市场模拟 | 架构预留 | 侧边栏灰置并标注「预留」；数据层与 system_id@version 设计已保证两模块共享电力系统模型 |

预留口子说明：
- 前端：侧边栏模块项已占位，后续扩展为可点击路由；六屏侧边栏均为同一组件，扩展时只需放开禁用态。
- 后端：数据模型按 system_id@version 全局共享，模块 2（市场模拟）可直接复用模块 1 的电力系统建模与运行边界数据；算法参数、任务引擎按模块命名空间隔离（如 planning.tasks / market.tasks）。

### 11.1 功能层级修订（2026-11-03 二轮）

- 删除「工作台」入口（无业务价值）。
- 侧边栏两级结构：
  - 电力系统规划：电力系统建模 / 运行边界 / 算法参数 / 结果分析 / 对比分析（5 个子模块）
  - 电力市场模拟：子模块待定义（占位）
- 业务流口径：默认先完成规划、再用市场模拟验证规划方案的收益/可行性；也支持跳过规划、直接开展市场仿真（两个模块并列、无强制前置）。市场模拟模块可复用规划产出的电力系统模型（system_id@version）与扩建后的电源结构作为输入。

### 11.2 三轮修订（2026-11-03 下午）

**① 屏① 电力系统建模：清单 Tab 化 + 拓扑弹窗**
- 机组 / 节点 / 线路 / 联络线四个清单改为页签切换（同一表格区），不再四卡平铺。
- 工具栏：拓扑可视化（蓝色描边+图标）、导入 CSV、导出 CSV、新增机组；统计行保留装机/已建/待建汇总。
- 「拓扑可视化」点击后弹出居中弹窗：6 节点网架图（含区外 X1/X2 联络线、待建机组橙点、机组挂接标注、图例），支持缩放/拖拽/点选高亮。

**② 全年 8760h 仿真口径（重大口径变更）**
- 运行边界数据维护由"单代表日 24h"改为**全年 8760h 逐时**：筛选行（年份 + 月签 1~12 月 + 数据对象），网格为 日期(行) × 24 时刻(列)，单对象全年 8,760 条记录；支持 CSV 导入/导出/模板，缺失补 0 并计入校验。
- 三张输入图表（负荷/新能源/区外来电）重绘为全年曲线（月份刻度 1~12 月）。
- ③④⑤⑥ 屏口径同步：方案摘要"运行边界 全年 8760h"、执行确认"T=8760h"、结果/对比图表标题与横轴改为全年口径。

**⚠ 对算法实现的影响（需在联调前决策）**
- 现有 Python 实现（v0.4）为单代表日 24h；全年 8760h 意味着运行层变量规模 ×365（约 200 万级变量）。
- Gurobi 受限许可证（2000 变量/约束）**无法**直接求解全年模型；可行路线：
  1) 商业许可证 + 全年单模型直解（内存/求解时间需评估）；
  2) 分块滚动求解（按月/周分块 + SOC 跨块衔接，近似解）；
  3) 典日 + 时序扩展（保留全年逐时数据，求解时抽样/聚类典型日加权）。
- 建议采用路线 3 作为默认（数据维护仍为 8760h），路线 1 作为高配选项。
