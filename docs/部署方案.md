# 部署与交付手册 —— 基于市场环境的电力系统规划仿真平台 v1.0

> 面向「要装到另一台电脑 / 交给别人用」的场景。照着做即可，不需要改代码。
> 只想在本机跑起来：看第 2 节的「三步启动」就够了。

---

## 1. 选择部署方式

| 场景 | 推荐方式 | 章节 |
|---|---|---|
| 自己的电脑，一个人用 | 本机直跑（Python + start.bat） | 2 |
| 办公室内网，几个人共用一个数据 | 一台机器跑服务，其他人浏览器访问 | 3 |
| 装到服务器长期运行、开机自启 | Docker 或 systemd / NSSM 注册服务 | 4、7 |
| 对方电脑没有外网（内网 / 实验室隔离机） | 离线依赖包 + 分发包 | 6 |
| 把现在这台机器上的数据一起搬走 | `python pack.py --with-data` | 5 |

**不需要联网也能用**：图表库已随包内置（`server/static/vendor/echarts.min.js`），页面不依赖外网 CDN。

---

## 2. 路线 A：本机直跑（单机，最常用）

### 2.1 环境要求

| 项 | 要求 | 备注 |
|---|---|---|
| 操作系统 | Windows 10/11、Ubuntu 20.04+、macOS 12+ | 64 位 |
| Python | **3.10 及以上** | 开发验证 3.13；一键启动脚本在 3.14 上同样验证通过 |
| 内存 | 4 GB 起；跑 720h 以上算例建议 8 GB | 求解是 CPU 密集型 |
| 磁盘 | 1 GB 空闲 | 程序约 1.2 MB 压缩包，算例结果按任务增长 |
| 网络 | 仅**首次安装依赖**需要外网 | 之后完全离线可用 |
| 求解器 | Gurobi（pip 自带受限许可） | 见第 8 节，全年算例需完整许可 |

### 2.2 Windows：三步启动

1. 安装 Python：https://www.python.org/downloads/ ，安装界面**必须勾选 “Add Python to PATH”**。
2. 解压分发包到任意目录（路径**不建议带空格或中文以外的特殊符号**，例如 `D:\powerplan`），双击 **`start.bat`**。
   - 首次运行自动做三件事：建 `.venv` 虚拟环境 → 装依赖 → 启动服务，约 1~3 分钟；
   - 窗口里出现 `Uvicorn running on http://0.0.0.0:8000` 即成功，浏览器会自动打开。
3. 想换端口：命令行执行 `start.bat 8080`。

> 关闭那个黑色窗口 = 停止服务。窗口在跑的时候不要关，否则页面会断开（已经提交的计算任务不受影响，重新打开页面即可看到结果）。

### 2.3 Linux / macOS

```bash
unzip 电力规划平台-v1.0-*.zip -d powerplan && cd powerplan
chmod +x start.sh
./start.sh            # 默认 8000，可 ./start.sh 8080
```

### 2.4 首次使用的两件事

- 打开后是**空库**（没有任何机组 / 节点 / 线路 / 联络线），这是设计如此：到「系统建模」新建系统后自己录入或 CSV 导入。
- 想先验证算法链路通不通：导入样例数据 —— 页面里上传 `data/sample/` 下的 CSV，或直接调 `POST /api/systems/from-sample`。

## 3. 路线 B：局域网共享（多人用同一份数据）

服务已经以 `--host 0.0.0.0` 启动，剩下的只是放行防火墙。

**1）查本机内网 IP**

```bat
ipconfig            :: Windows，看「IPv4 地址」，如 192.168.1.23
hostname -I         :: Linux
```

**2）放行 8000 端口**

```bat
:: Windows（管理员命令行）
netsh advfirewall firewall add rule name="规划平台8000" dir=in action=allow protocol=TCP localport=8000
```
```bash
# Linux（ufw）
sudo ufw allow 8000/tcp
```

**3）同事访问** `http://192.168.1.23:8000`

注意事项：

- **同一个数据库只能有一个服务进程**。不要在两台机器上各跑一份然后指向同一个 `platform.db`（网络盘也不行），SQLite 会锁冲突。
- 平台**没有登录与权限体系**，只适合内网 / 可信网络。要放到公网，必须前置 Nginx + 认证（basic auth 或 SSO）或走 VPN，详见第 9 节。
- 多人同时「浏览 / 导出」没问题；**求解任务建议排队提交**，几台任务同时跑会抢 CPU 和内存。

## 4. 路线 C：Docker（服务器 / 环境干净优先）

```bash
docker compose up -d --build          # 访问 http://<主机IP>:8000
docker compose logs -f                # 看日志
docker compose down                   # 停止
```

- 数据持久化在命名卷 `platform-data`（容器内 `/data`），`docker compose down` 不会删数据；
  彻底清理才用 `docker compose down -v`（**会删库**，慎用）。
- 镜像内已包含 `server/`、`algorithm/`、`data/sample/`；Gurobi 受限许可随 pip 包进来，小算例开箱可跑。
- 完整许可（WLS）在 `docker-compose.yml` 里取消注释 `WLSACCESSID / WLSSECRET / LICENSEID` 三个环境变量即可；命名用户许可则把 `gurobi.lic` 挂载进容器并用 `GRB_LICENSE_FILE` 指向它。

**离线服务器**：在联网机 `docker compose build` 后 `docker save planning-platform -o platform.tar`，拷过去 `docker load -i platform.tar`，再 `docker compose up -d`。

## 5. 数据迁移 / 备份

平台的全部状态只有两处：

| 路径 | 内容 |
|---|---|
| `platform.db` | 系统版本、四清单、运行边界、算法参数、任务记录（SQLite 单文件） |
| `platform_data/jobs/<id>/` | 每次计算的算例 CSV、结果 CSV、日志 |

**迁移到新机器（推荐）**

```bash
# 在旧机器、项目根目录执行（会自动做 WAL 落盘，避免拷到半截数据）
python pack.py --with-data
# 把 dist/电力规划平台-v1.0-<日期>.zip 拷到新机器，解压，start.bat
```

**手工方式**：先停服务，再拷 `platform.db` 和 `platform_data/` 整个目录（**停止服务这一步不能省**，WAL 模式下边写边拷可能得到损坏的库）。

**日常备份**：定期复制这两个路径即可；建议每周一次，保留多份。程序升级不影响这两项数据。

## 6. 路线 D：离线 / 内网机器安装

依赖包必须与目标机器的 **操作系统 + Python 版本** 匹配，所以在一台“同款”联网机上下载。

```bash
# ① 联网机（与目标机同系统、同 Python 大版本）
python -m pip download -r requirements.txt -d wheelhouse

# ② 把 wheelhouse/ 连同分发包一起拷到目标机，解压后在项目目录：
python -m venv .venv
.venv\Scripts\python.exe -m pip install --no-index --find-links wheelhouse -r requirements.txt   # Windows
./.venv/bin/python      -m pip install --no-index --find-links wheelhouse -r requirements.txt   # Linux
```

装好后直接 `start.bat` 会把依赖检查跳过（已满足），正常启动。

> `gurobipy` 各平台都有 wheel，无需编译；但如果目标机是 ARM / 非主流架构，请先确认 PyPI 上有对应 wheel。

## 7. 长期运行（开机自启）

**Windows（NSSM，最省事）**

```bat
nssm install PowerPlan "D:\powerplan\.venv\Scripts\python.exe" "-m uvicorn server.app:app --host 0.0.0.0 --port 8000"
nssm set PowerPlan AppDirectory "D:\powerplan"
nssm set PowerPlan Start SERVICE_AUTO_START
nssm start PowerPlan
```

**Linux（systemd）**

```ini
# /etc/systemd/system/powerplan.service
[Unit]
Description=Power Planning Platform
After=network.target

[Service]
WorkingDirectory=/opt/powerplan
ExecStart=/opt/powerplan/.venv/bin/python -m uvicorn server.app:app --host 0.0.0.0 --port 8000
Restart=always
User=powerplan

[Install]
WantedBy=multi-user.target
```
```bash
sudo systemctl daemon-reload && sudo systemctl enable --now powerplan
```

**Docker**：`docker-compose.yml` 已带 `restart: unless-stopped`，宿主机重启后自动拉起。

## 8. Gurobi 许可（部署时最容易卡住的一环）

`pip install gurobipy` 装完即可用，但它自带的是 **size-limited（受限）许可**：模型变量数或约束数超过 **2000** 会直接报 `Model too large for size-limited license`。

| 你的算例 | 受限许可能否跑 | 建议 |
|---|---|---|
| 计算周期 24h（代表日） | ✅ 可以 | 默认，最快 |
| 计算周期 168h（一周） | ✅ 通常可以 | 需先看「算法参数」页的规模预估是否飘红 |
| 计算周期 720h（一月） | ⚠️ 视系统规模，多半超限 | 减少机组/线路数量可试 |
| 全年 8760h | ❌ 不行 | 需完整许可 |

**判断当前是什么许可**：跑一个算例，若求解日志/任务详情里出现 `Restricted license - for non-production use only`，就是受限许可。

**安装完整许可（学术免费）**

1. 用学校邮箱在 https://www.gurobi.com/academia/academic-program-and-licenses/ 申请 WLS（Web License Service）学术许可；
2. 拿到三串参数后，任选其一：
   - 写进环境变量：`WLSACCESSID`、`WLSSECRET`、`LICENSEID`（Docker 部署就用这种方式）；
   - 或把下载的 `gurobi.lic` 放到 `C:\Users\<用户名>\gurobi.lic`（Linux：`~/gurobi.lic`），或设 `GRB_LICENSE_FILE` 指向它；
3. 重启服务，重新提交任务确认日志里不再出现 `Restricted license`。

**注意**：命名用户许可与机器绑定，换电脑/换容器 hostname 会失效，需要在 Gurobi 官网重新激活或改用 WLS（浮动、不绑机器）。

## 9. 安全提醒

- 平台**无账号体系、无鉴权**：任何能访问到端口的人都能改数据、跑计算、删系统。
- 因此：**只在内网使用**；确需公网访问，用 Nginx 反代 + 认证（示例：`auth_basic`）+ HTTPS，或直接走 VPN，别把 8000 直接映射到公网。
- 交付给他人的机器，建议关掉不需要的端口暴露，`host` 改成 `127.0.0.1` 即只允许本机访问。

---

## 10. 升级到新版本

1. 停服务；
2. 用新分发包覆盖 `server/`、`algorithm/`、`docs/`、`start.*`、`requirements.txt`（**不要覆盖 `platform.db` 和 `platform_data/`**）；
3. 若有依赖变化，`start.bat` 首次启动会自动补装；
4. 启动后服务会**自动执行数据库结构迁移**（新增字段自动补列），历史数据保留。

保险起见，升级前先按第 5 节备份一次。

## 11. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 双击 `start.bat` 一闪而过 | 没装 Python / 没勾 PATH | 命令行运行 `python --version` 确认；重装并勾选 Add to PATH |
| `[错误] 依赖安装失败` | 访问 PyPI 超时 | 加镜像：`-i https://pypi.tuna.tsinghua.edu.cn/simple`；或走第 6 节离线安装 |
| 页面打不开，窗口没报错 | 端口被占用 | `netstat -ano \| findstr :8000` 找到 PID 结束，或换端口 `start.bat 8080` |
| 本机能开、同事打不开 | 防火墙 / 不同网段 | 放行 8000（第 3 节）；确认在同一内网；用 `http://IP:8000` 而不是 `localhost` |
| 页面能开但图表空白 | 浏览器缓存了旧页面 / 图表库未加载 | `Ctrl+F5` 强制刷新；确认 `server/static/vendor/echarts.min.js` 存在 |
| 解压后中文文件名乱码（`data/sample/*.csv`） | 用了不识别 UTF-8 的旧版解压工具 | 用 Windows 资源管理器或 7-Zip 重新解压；乱码会导致「导入样例」报缺文件 |
| 提交任务立即失败：`Model too large for size-limited license` | 算例规模超受限许可 | 「算法参数 → 计算周期」改 24h/168h/720h；或装完整许可（第 8 节） |
| `No license found` / `License expired` | 完整许可未生效 | 检查 `gurobi.lic` 路径、`GRB_LICENSE_FILE`、WLS 三个环境变量 |
| CSV 导入报错「第 N 行」 | 表头或取值不合规范 | 按提示行号改；导出模板后照格式填最稳；编码 utf-8 或 GBK 都可识别 |
| 任务一直 `running` 不动 | 求解时间长（大规模算例） | 看任务日志；可点「取消任务」，或降低计算周期 |
| 数据库 `database is locked` | 多个服务进程指向同一个库 | 只保留一个服务实例 |

日志位置：服务窗口（前台）/ `docker compose logs`（容器）；单个任务的失败原因在「执行计算」页任务详情里。
